## 2. Назначение и целевая аудитория

Сервис позволяет проводить небольшие опросы в учебной группе:
создать вопрос, предложить варианты ответа, собрать голоса,
посмотреть результаты и завершить голосование.

Целевая аудитория — участники и организаторы учебных обсуждений.
В текущей версии роли технически не разделены: создание, голосование и закрытие
доступны любому посетителю.

Учебная цель — продемонстрировать путь приложения от исходного кода и истории Git
до автоматических тестов, CI, получения artifact и понятного локального запуска.

## 3. Функциональные возможности

1. Создание опроса с вопросом и 2–8 вариантами ответа.
2. Получение списка опросов, новые отображаются первыми.
3. Просмотр отдельного опроса по идентификатору.
4. Голосование за выбранный вариант.
5. Получение количества голосов и процентов по каждому варианту.
6. Закрытие опроса с запретом дальнейшего голосования.
7. Работа через веб-страницу или API.
8. Проверка состояния и получение версии приложения.

Основной сценарий: создать опрос → выбрать вариант → проголосовать →
посмотреть результаты → закрыть опрос. После закрытия новые голоса
отклоняются с HTTP 409, а результаты остаются доступными.

## 4. Технологии и архитектура

| Компонент | Решение |
|---|---|
| Язык | Python 3.12 |
| API | FastAPI |
| Проверка данных | Pydantic |
| ASGI-сервер | Uvicorn |
| Интерфейс | HTML, CSS, JavaScript и Fetch API |
| Хранилище | Словарь в памяти одного процесса |
| Настройки | Переменные окружения и `python-dotenv` |
| Тестирование | pytest, FastAPI TestClient, httpx |
| Контроль версий | Git и GitHub |
| Автоматические проверки | GitHub Actions |

Браузер отправляет HTTP-запросы в FastAPI. Приложение проверяет входные данные,
читает или изменяет словарь опросов и возвращает JSON. Веб-страница показывает
вопросы, варианты, состояние голосования и результаты.

Исполняемый файл — [app_final.py](app_final.py), интерфейс — [index.html](index.html).
Отдельная база данных, фронтенд-сборка и внешние API не требуются.

## 5. API и проверка данных

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/` | Веб-интерфейс |
| POST | `/polls` | Создание опроса |
| GET | `/polls` | Список опросов |
| GET | `/polls/{poll_id}` | Просмотр опроса |
| POST | `/polls/{poll_id}/votes` | Голосование |
| GET | `/polls/{poll_id}/results` | Результаты |
| POST | `/polls/{poll_id}/close` | Закрытие опроса |
| GET | `/health` | Состояние процесса |
| GET | `/version` | Версия приложения |

Вопрос содержит от 1 до 200 символов, вариант — от 1 до 100.
Пробелы по краям удаляются. Повторяющиеся варианты, включая различающиеся
только регистром, не принимаются. Идентификатор варианта должен быть
положительным целым числом и существовать в выбранном опросе.

Основные коды ответов: 200 — успешная операция; 201 — создание опроса;
404 — опрос не найден; 409 — голосование в закрытом опросе;
422 — неверные входные данные. Проценты округляются до одного знака.

## 6. Запуск, конфигурация и диагностика

Нужны Python 3.12 и `venv`; для получения репозитория нужен Git.
Установка из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
```

Обычный запуск:

```bash
python -m uvicorn app_final:app --host 127.0.0.1 --port 8002 --workers 1
```

Веб-страница: <http://127.0.0.1:8002/>.
Интерактивная документация: <http://127.0.0.1:8002/docs>.
Остановка — `Ctrl+C`. Для разработки можно использовать `--reload` вместо
`--workers 1`; перезапуск очищает данные в памяти.

Настройка `APP_VERSION` задаёт версию, возвращаемую `/version`.
При отсутствии значения используется `0.1.0`. Пример настроек хранится
в [.env.example](.env.example). Настоящий `.env` исключён из Git.
Переменная процесса имеет приоритет над `.env`.

Логи запуска, остановки, создания и закрытия опросов, принятых голосов
выводятся в терминал с сервером. Uvicorn дополнительно выводит запросы
и HTTP-статусы. Для диагностики используются `/health`, `/version`,
логи и таблица устранения ошибок в README.

## 7. Тестирование

Набор [test_app.py](test_app.py) содержит 35 проверок с учётом параметризации:

- служебные маршруты и версия из окружения;
- создание, получение и порядок опросов;
- подсчёт голосов и процентов, независимость опросов;
- закрытие, повторное закрытие и сохранение результатов;
- неверные варианты и типы данных;
- неизвестные опросы;
- обязательные поля, ограничения длины и количества вариантов;
- повторяющиеся ответы и обработка пробелов.

Команды запуска:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -v
```

Каждый тест получает очищенное хранилище и сброшенный генератор ID.
Отдельный сервер и обращения к внешним сайтам не нужны.
Результат последнего выполнения следует проверить перед сдачей.

## 8. CI и поставка приложения

Workflow: [Poll Service CI](https://github.com/aston3/poll-service/actions/workflows/ci.yml).
Конфигурация: [.github/workflows/ci.yml](.github/workflows/ci.yml).
События запуска: push, pull request, ручной запуск.

- Джоба `test` получает код, подготавливает Python 3.12, устанавливает зависимости,
  проверяет их совместимость и запускает тесты.
- Джоба `package` выполняется после успешной `test` через `needs: test`,
  делает собственный checkout и сохраняет artifact.

Artifact называется `poll-service` и хранится 7 дней. В него входят
`app_final.py`, `index.html`, `requirements.txt`, `README.md`, `.env.example`.
Тесты и зависимости тестирования доступны в репозитории и в artifact не входят.
Установленное виртуальное окружение и настоящий `.env` не поставляются.
Этот паспорт также не включён в текущий список файлов artifact.

Artifact скачивается со страницы успешного запуска GitHub Actions.
После распаковки ZIP приложение устанавливается и запускается по README.
Автоматическое развёртывание на сервере не выполняется.

## 9. Ограничения и возможное развитие

| Ограничение | Последствие |
|---|---|
| Хранение в памяти | Все опросы и голоса исчезают после перезапуска |
| Один процесс | Несколько workers имели бы независимые наборы данных |
| Нет регистрации | Один посетитель может проголосовать несколько раз |
| Нет проверки владельца | Любой посетитель может закрыть опрос |
| Локальный запуск | Адрес `127.0.0.1` недоступен другим компьютерам |
| Округление процентов | Сумма может немного отличаться от 100% |

Возможное развитие: постоянное хранилище, роли и контроль доступа,
ограничение повторных голосов, контейнеризация и размещение на сервере.
Это направления развития, а не реализованные функции.
